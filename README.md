# roundtable

终端可玩、可跨进程续玩的单场回合制遭遇。Node.js 24 ES modules，无外部运行依赖。

## 运行

需要 Node.js 24：

```sh
node app.js --help        # 或 -h；无参数也显示帮助
```

## 命令

```sh
# 新建遭遇（已有存档不会被覆盖；角色名非空）
node app.js new ./save.json --name "亚瑟"

# 查看当前状态 / 行动记录（只读，不改写存档）
node app.js status ./save.json
node app.js log ./save.json

# 提交行动：attack 攻击 / defend 防御 / potion 喝药
node app.js act ./save.json attack
```

不同存档路径互不影响；每次调用自动读取所选存档，行动整体原子落盘，
关闭进程后重新查看或继续，状态、回合与记录完全一致。

## 固定规则

- 角色：生命 10/10，攻击 4，初始 1 瓶治疗药；敌人：生命 12/12，攻击 3；从第 1 回合开始。
- `attack`：扣除敌人 4 点生命，敌人死亡立即胜利且不反击。
- `defend`：仅把本回合敌方伤害降为 1，不叠加、不消耗物品。
- `potion`：消耗 1 瓶药恢复 6 点生命（不超过上限）；生命已满或无药时拒绝。
- 敌人存活则反击（否则受到 3 点伤害），角色生命归 0 立即失败；双方存活进入下一回合。
- 无效行动不触发反击、不推进回合、不消耗物品、不追加记录；终局后只能查看。
- 无随机数。记录按回合列出双方行动、实际伤害/治疗量与结算后双方生命。

## 退出码与存档安全

- `0` 成功；`1` 运行/存档错误（存档不存在、损坏、数值越界、结局与生命矛盾、保存失败等）；`2` 参数错误。
- 存档为本地 JSON。写入采用同目录临时文件 + 原子改名 + `fsync`，
  进程中断只会读到行动前或行动后的完整状态；新建用硬链接防覆盖，
  失败的新建不会留下会被误认作有效存档的文件。损坏的存档不会被自动清空或覆盖。
