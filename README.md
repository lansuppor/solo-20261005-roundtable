# roundtable

回合制战役与存档产品的本地命令行入口。单场遭遇或两场连续战役，可跨进程续玩。
需要 Node.js 24，无外部运行依赖。

## 用法

```sh
node app.js                              # 显示帮助
node app.js --help | -h                  # 显示帮助
node app.js new <存档路径> <角色名>       # 新建单场遭遇（存档已存在则报错，不覆盖）
node app.js campaign <存档路径> <角色名>  # 新建两场连续战役（存档已存在则报错，不覆盖）
node app.js status <存档路径>            # 查看当前状态
node app.js act <存档路径> <行动>        # 提交行动：attack | defend | potion
node app.js next <存档路径>              # 战役第一场胜利后进入第二场
node app.js log <存档路径>               # 查看行动记录（战役含场次、奖励与场间切换）
```

存档为本地 JSON 文件，路径自定；不同存档互不影响。每次调用自动读取所选存档，
`status` 与 `log` 不会改写存档。`new` 创建的单场存档始终按单场规则游玩，
不会自动变成战役；`campaign` 创建的战役存档从第一场开始。

## 规则

- 角色：生命上限 10、攻击 4、治疗药 1 瓶（恢复 6，不超过上限；满血或无药时拒绝）。
- 敌人：单场遭遇与战役第一场为生命 12、攻击 3；战役第二场为生命 16、攻击 3。
  每场回合从 1 开始，规则固定，不使用随机数。
- 行动：`attack` 扣敌人 4 点生命；`defend` 使本回合敌方伤害降为 1（不叠加）；
  `potion` 消耗一瓶并恢复 6 点生命。
- 每个有效行动构成完整回合：先结算玩家效果，敌人死亡立即胜利且不反击；
  否则敌人反击，角色死亡立即失败；双方存活则进入下一回合。生命最低为 0。
- 无效行动不触发反击、不推进回合、不消耗物品、不追加记录。
- 单场终局后拒绝继续行动，但仍可查看状态和记录。

## 战役（两场连续）

- 第一场胜利的致命回合同时发放奖励：恢复角色 4 点生命（不超过 10）、增加 1 瓶药，
  并进入等待下一场状态；此时战斗行动被拒绝，只能用 `next` 进入第二场。
- 只有等待状态可进入第二场：保留角色生命和药瓶，敌人与回合重新初始化，奖励不重复发放。
  进入第二场后再次 `next` 会被拒绝且不改动存档。
- 第二场胜利即完成战役；任何一场角色死亡均结束为战役失败，
  此后禁止进入下一场和继续行动。
- `status` 显示当前场次、当前或结束回合、角色资源、敌人生命、等待状态及战役结局；
  `log` 按发生顺序保留两场的完整回合记录，标明场次、实际伤害和治疗、结算后生命，
  并显示首次胜利奖励和场间切换。

## 存档可靠性

- 有效行动或场间切换的战斗结果、奖励、进度与记录作为一个整体
  原子写入（临时文件 + fsync + rename），进程中断只会读到操作前或操作后的完整状态，
  不会重复领取奖励或丢失前场记录。
- 新建通过硬链接落位，已有存档不会被覆盖；失败的新建不留下可误认的存档文件。
- 读取时校验存档完整性（含按固定规则重放行动记录；战役存档还会校验两场行动、
  奖励与场间切换能否按规则重放）。内容损坏、数值越界、重复奖励、非法切换或
  结局与生命矛盾时拒绝继续，不自动清空或覆盖。

退出码：0 成功；1 业务/运行错误（含存档问题、无效行动、保存失败）；2 参数错误
（含未知命令与未知行动）。
